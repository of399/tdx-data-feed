## 📈 统计分布：能力的"厚度"剖面

```
显式且扎实  ████████████  5  (线性代数/概率统计/数值分析/优化/建模)
隐性在用    ██████        3  (微积分/微分方程/泛函)
雏形/可选   ██████        3  (离散-图论/拓扑/几何)
无关        ████          2  (代数/数论)
```

**关键不对称**：底层（线性代数、优化）已达机构级，**顶层（统计推断）却是业余级**。这导致一个尴尬局面——用最严谨的 ERC 风险平价，去配置一组统计上无法拒绝"纯随机"的因子（今日实测 IC 正向率 48.5%）。**工程精度远高于信号置信度**，这是当前最需要纠正的结构性失衡。

**依赖侧证据**：`statsmodels>=0.14.0` 已在 `requirements.txt` 声明却全仓库 0 处 import；`scipy` 仅用到 `stats.pearsonr/spearmanr/skew`，`optimize`/`integrate`/`interpolate` 三个子包从未触碰。

## ⚠️ 风险提示

1. 历史回测不代表未来收益；本审计基于 2026-10-15 代码快照，代码演进后结论需重新验证
2. **`factor_significance.py` 自身注释已承认**：22 个因子做单点检验 → 约 **70% 假阳性**。在未做 FDR 校正前，任何"显著因子"结论都不可信
3. Optuna 150 trials + 27 组参数网格 = 大量试验次数，**夏普比率存在严重选择偏差**（需 Deflated Sharpe 折算），当前 v2「胜率 35.3% / 盈亏比 2.71」的显著性未经多重试验校正
4. 引入 `cvxpy` 属新增重量级依赖（含 SCS/ECOS 求解器），需先在 `venv` 验证与 py3.14 + torch 2.11+cu128 的 ABI 兼容，避免重演 torchvision 错配事故
5. 北交所（920XXX，bj 前缀）流动性低、滑点放大（成本模型已设 0.3% vs 主板 0.1%），任何仓位/风险模型升级**必须单独对北交所子集做敏感性检验**，不可全市场混算
6. 数学工具升级只提升"测量精度"，**不创造 alpha**。今日实证：代理因子 IC≈-0.012 → 再精密的 ERC 也救不了零信号；真实估值数据（`--mode real`）到位前，优先级应低于数据源建设
7. **普四卷对本项目投入产出比约 23.53%，且对两项 P0 帮助为 0** —— 若目标是提升策略数学严谨度，优先补统计推断（多重检验/Deflated Sharpe/HAC）与凸优化（cvxpy）；四卷更适合作为理论修养而非工程投入
8. 频域方法（FFT 周期检测）在金融序列上**极易过拟合**：金融信噪比极低，"看起来有周期"的频谱峰值需用置换检验（随机打乱时间序列表重算频谱，比较峰值分布）证伪后方可采信
