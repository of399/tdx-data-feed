## 1. 缺陷的三行代码形状

| 位置 | 现状 | 后果 |
|---|---|---|
| `scripts/train_daban_model.py:135` | `limit_val = get_limit(code)` | 标签判定 `close[t+1]/close[t]-1 >= limit_val` 恒用**当日生效**的档（并轨后=10%） |
| `tdxfeed/features_5d.py:148` | `limit = get_limit(code)` | 特征第 0 维 `limit` 同样恒用当日档；`name` 也没传 ⇒ 连"这只票是 ST"这个信息都没进函数 |
| `tdxfeed/features_5d.py:179` | `"is_st": 0,` | 第 15 列（0 基 `dim=14`）写死 0；注释自己写了"由调用方按需通过 name 覆盖"，而调用方没有 |

权威层是支持日期的——`tdxfeed/features_5d.py:64` 的签名就是
`get_limit(code: str, name: str = "", on_date=None) -> float`，docstring 要求历史区间传交易日；
`tdxfeed/execution/limits.py:27-29` 有 `LIMIT_RATIO_ST_MAIN_OLD` / `LIMIT_RATIO_ST_MAIN` /
`MAIN_ST_RULE_CHANGE_DATE` 三个常量，按日期分段的 `limit_ratio()` 分支真实存在并有测试
（`tests/test_features_5d.py:46-47` 断言 `on_date="2026-07-03"` 的 ST 主板给 0.045）。
**缺陷不在权威层，在调用层没把日期传进去。**

## 2. 口径：用的是判定契约 `limit_threshold`，不是挂单价契约

仓库里有两个都叫"涨停比例"的东西，**不可互换**，本轮全程只用第一个：

| 契约 | 函数 | 定义 | 用途 |
|---|---|---|---|
| **判定** | `limit_threshold(code, is_st, on_date)` | `limit_ratio - DEFAULT_THRESHOLD_BUFFER`（默认再减 0.005），比较时还要减 `RET_TOLERANCE`（0.001） | 回答"这算不算涨停" ⇒ 标签 |
| 挂单价 | `limit_ratio` + `limit_up_price(prev_close, ratio)` | `round(prev_close × (1+ratio), 2)` | 回答"涨停价是几块几" ⇒ 下单/撮合 |

把两者混用的错法很具体：主板非 ST 的 ratio=0.10，判定值是 **0.095**，而 `limit_up_price` 给的是
价格不是比例；如果拿 0.10 当判定值，就会把涨幅 9.6%（未触及涨停价，因为四舍五入后涨停价对应
的实际涨幅是 0.0997…0.1003 之间）误判成正样本，同时把 0.095 这条真实分界线挪掉。反过来拿
0.095 去算挂单价则会在撮合侧报出一个不存在的价位。所以下面所有阈值都是
`limit_threshold(...)` 现算再减 `RET_TOLERANCE` 得来的：

| 量 | 变量 | 现算值 | 来源 |
|---|---|---:|---|
| 主板现役判定 | `DEC_MAIN` | 0.094 | `limit_threshold("600000") - RET_TOLERANCE` |
| 双创现役判定 | `DEC_GEM` | 0.194 | `limit_threshold("300000") - RET_TOLERANCE` |
| 并轨前主板 ST 判定 | `DEC_ST_PRE` | 0.044 | `limit_threshold("600000", is_st=True, on_date=2026-07-05) - RET_TOLERANCE` |
| 并轨日 | `RULE_DAY` | 2026-07-06 | `MAIN_ST_RULE_CHANGE_DATE` |

`scripts/audit_daban_st_tier_pollution.py` 里**没有这四个字面量**，全部从
`tdxfeed.execution.limits` 导入后现算（仓库有单源约定，新增手抄会被容差守卫拦）。

标签轴的另一个要点：翻转判定用的是 `close[i+1]/close[i]-1`（前向收益），与
`train_daban_model.py:162` 同轴；而判"这只票当时是不是 5% 档"用的是逐日涨幅
`close[i]/close[i-1]-1`（当日收益）。**这两个轴不能共用一个数组**——本轮第一版就踩了：
拿 T-1→T 的收益当标签轴，全市场翻转数算成 57,539，比参考实现多 4,600 行；分成
`_pct_today()` / `_pct_forward()` 后落回 52,919（§9.3）。

## 3. 三层证据，按强度排序

### 3.1 硬证据：训练矩阵里一条 5% 档的票都没进去

现役产物 `data/double_up/d_signal_5d_model_daban.txt`（mtime 2026-10-19 17:30，实测）的
`feature_infos` 第 0 维：

```
模型 = d_signal_5d_model_daban.txt
feature_names=29  feature_infos 解析出 29 段  对齐=OK
  limit                dim= 0  feature_infos=[0.095000000000000001:0.19500000000000001]
                       ⇒ 区间 [0.095, 0.195]；5% 档的判定值 0.044 落在该区间内？False
  is_st                dim=14  feature_infos=none
  is_bj                dim=16  feature_infos=none
```

`limit` 维的**最小观测值是 0.095** ⇒ 训练矩阵里不存在任何一条取值低于 0.095 的样本，
也就是没有任何一天被当作 5% 档。这不是"模型没学会用这一维"，是**这一维的历史值就是错的**。
`is_st` / `is_bj` 两段是 `none`：LightGBM 的 `none` 表示该列在训练集里是常数列——比"没传 name"
更强的一层事实是**模型连一个可看的 ST 列都没有**。旁证：`is_bj` 也应是 `none`，北交所按设计被剔除，
所以 `none` 的解释在这一维上已被独立验证过（`docs/research/2026-11-04-stage1-union47-dual-run.md`
里同一现象记为"常数列在 `rank_ic` 里直接给 NaN"）。

解析注意：`feature_infos` 的段必须按 `re.findall(r"\[[^\]]*\]|none", infos)` 切。按方括号硬切会把
`none` 段丢掉，列名与段就错位——本轮第一版因此读出 27 段 / 29 维、并把 `is_st` 读成一个不存在的区间。

### 3.3 名单侧：日期化 ST 证据能拿到多少（结论已在 2026-11-05 下午翻正）

**这一节推翻了本快照初稿与任务背景里那句"仓库内无日期化 ST 源"。** 通达信侧确实能拿到带日期的
特别处理台账，但**条数既少又不均**（全市场补测：条目数分布 `0:4739 / 1:182 / 2:233 / 3:60 / 4:11 / 5:4`、
观测最大 5 条 ⇒ 没有"每票 N 条"这种窗口上限，初稿那句"每票最多 3 条"是被否证的样本外推；
真正卡住覆盖面的是 **4,739/5,229 = 90.63%** 的票整栏「暂无数据」，时间深度见 §3.3.1b），所以正确的说法不是"修不了"，而是
**面板可重建、但权威段很短**：我实测的 15 只里，台账最早一条记录的中位数是 **2026-03-31**、
最早的一只也只到 **2023-01-07** ⇒ 15 只这个小样本里看不到 2023 年之前的权威记录。
**这句只是样本的形状**：全市场跑完后 F10 侧最早实施到 **2014-08-06**，深市另有 1998-04-28 起的
带日期名称面板（§3.3.1b）⇒ 真正只能靠价格反推的是**沪市 2014 年之前**那一段，不是"2023 之前"。
逐源能力、样本量与我自己的复核见 §3.3.1–§3.3.6；污染量为什么仍然必须报成带见 §5（判定理由已按
台账深度重写）。

`rule` 子命令给出的是"价格反推"这条判据自身的证据强度（当前名单当 ST 的那 144 只 vs 随机非 ST
对照 144 只，pre 段取并轨前最后 120 个交易日；退出码 0）：

```
名单总数=5221  主板 ST=144（本轮看 144）  主板非 ST=3053（对照组 144）
有效逐票条数=575  缺失日线文件=0
[pre /ST     ] 票数= 144  交易日= 17,280  正收益 p99.5 中位=0.0590  单票最大涨幅中位=0.0696
[pre /CONTROL] 票数= 143  交易日= 17,160  正收益 p99.5 中位=0.0997  单票最大涨幅中位=0.1001
[post/ST     ] 票数= 144  交易日= 11,551  正收益 p99.5 中位=0.0848  单票最大涨幅中位=0.0989
[post/CONTROL] 票数= 144  交易日= 11,605  正收益 p99.5 中位=0.0794  单票最大涨幅中位=0.0997

=== 逐票前后对照（287 只两段都有数据；pre=并轨前最后 120 个交易日）===
  pre 段从未达到 10% 档判定值 0.094 的票数 = 128 / 287
  post 段至少一天达到 0.094 的票数 = 156 / 287
  pre 从未够着 10% 档 且 post 够着了（并轨解锁的形状）= 54 只
  pre 段就已越过 0.094 的票数 = 159
```

方向是对的：**并轨前 ST 组的涨幅上限（p99.5 中位 0.0590、单票最大涨幅中位 0.0696）明显压在 5% 档一侧，
而对照组在同一时段是 0.0997 / 0.1001**——贴着 10% 档。并有 54 只（18.8%）呈现"pre 从未够着 10% 档、
post 够着了"这条只有规则变更才能解释的形状。

但**逐票归因不可靠**：287 只里有 **159 只（55.4%）在并轨前就已越过 0.094**，反例比正面样本还多。
原因不是规则没变，是**名单是今天的**：今天叫 ST 的票里大部分在当时并不叫 ST（改名是事件驱动的），
把今日名单当"当时是 ST"就必然错。`pre/ST` 那 0.0590 的中位正是这批混合样本的位置——
它在 5% 与 10% 之间，两边都不贴。**所以"按今日名单直接算污染量"不成立，污染量仍来自 §4 的
价格反推并带 §5 的区间**；台账的作用是把反推**可裁定的那一小段**（实测最早也只到 2023-01-07，
多数票只到 2026 年）换成权威判定，不是把整条曲线换成权威（§3.3.6）。

#### 3.3.1b 同日傍晚补测：全市场跑完后本节有两处被自己推翻（A 批次）

A 批次把 F10 台账跑完了全市场（`scripts/collect_st_history.py f10`，宇宙 5,229 只 = 5,237 个
active 日线文件 − 8 个指数文件；`ok=5,158`、续跑 71 只、**失败 0**，500 秒 / 10.3 只每秒，
退出码 0）。上面那张 15 只表的两条结论因此要改：

1. **「每票最多 3 条」不成立，而且这句问错了对象。** 全市场条目数分布 =
   `{0: 4739, 1: 182, 2: 233, 3: 60, 4: 11, 5: 4}` ⇒ 观测**最大 5 条**，不存在"硬上限 3"
   （4 条的 11 只：`600595 600759 603007 603188 000430 000629 000792 000796 000809 002656 300338`
   ——转给我的那份清单**少了 `300338`**，我逐行数出来是 11 只；
   5 条的 4 只：`600710 000697 000908 300506`）。

#### 3.3.4 可达性：**要按能力分档说**——F10/板块可用，K 线不可用（这条推翻"TDX 直连可用"这句笼统话）

15:0x 我对 `pytdx` 的 `hq_hosts` **前 14 台逐台分三档**实测（同一台机上分别验
connect / bars / f10；判据不是"连上了"，而是**该通道真返回了非空数据**）：

```
connect（TCP + 协议握手） = 6/14
bars（真 K 线非空）        = 0/14    ← 连上的 6 台，get_security_bars / get_index_bars 全 0 根
f10（栏目 + 正文非空）     = 6/14    ← 与 connect 可用的正是同一批
select_server(want="bars") = None，原因统计 {tcp_timeout: 6, tcp_refused: 2, bars_empty: 6}（试 14 台 / 12.1s）
```

所以能力分档的结论要这样写，**别再写"TDX 直连可用"或"TDX 被封锁"这两种都不对的笼统话**：

| 端点 | 本环境 | 用途 |
|---|---|---|
| `get_company_info_category` / `_content`（F10 段落） | **可用**（6 台） | 本批 ST 台账 5,229 只就是走这条 |
| `get_and_parse_block_info("block_gn.dat")`（板块文件） | **可用**（同台） | 当日 ST 成员 198 只 / 1,379,375 行 |
| `get_security_bars` / `get_index_bars`（K 线、指数） | **不可用**（0/14） | 日线与指数的实际权威通道**仍然是 Sina** |

**这条与选主那一修是两件事，不许混**：`_default_server()` 取 `hq_hosts[0]`（一台死的
`218.85.139.19`）让每次构造白等 15 秒，这一修消掉的是白等与"把 TCP 通当成可用"，
把失败变成带原因计数的可见状态；**它不会把通达信侧的 K 线接回来**——
即便换成可达主机，bars 档仍然 0/14。因此 `MootdxSource()` 在 K 线用途上按契约直接抛
`RuntimeError` 带统计（实测输出即上面那行 `bars_empty: 6`），由 `full_sync.download_indices`
接住并全程回落 Sina；原来那句"本环境 TDX 被封锁"的注释已按实测改成能力分档表述。
下一轮若想给日线换通道，要换的是**数据源**（或别的网络出口），不是主机清单里的下一台。

另有一条独立的取证坑（与上面并列，都是本轮踩过）：
- 另一会话那支 `/tmp/probe_f10.py` 硬编码的两台（`218.6.170.47`、`218.85.139.19`）**都连不上**，
  脚本打印 `NO_SERVER`、**真实退出码 1**（我最初用 `| head` 取到的是 head 的 0，重跑不用管道才拿到 1）。
  ⇒ 单台连不上不等于通道不可达，反之单台连上也不等于通道可用——两个方向都要按档实测。
- 如果 F10/block 这类栏目只有通达信协议提供，那么修复链需要新增一条"pytdx 直连"通道，
  而不是复用现有的 Sina 兜底——**Sina 给不了这些段落**（这条仍成立，且与 bars 不可用不矛盾）。

#### 3.3.6 互证结果与判据精度（正式写入，标明样本量）

调研员的互证（**样本量：41 只票 / 2,974 票日**）：

| 判据 | 实测 | 读法 |
|---|---|---|
| 一致性反证 | 台账判 ST 的 **2,974 个票日里，当日 `|pct| > 5.8%` 的是 0 个** | 硬：ST 期间不可能涨过 5% 上限（并轨前） ⇒ 台账与价格不矛盾 |
| 票级 | 41 只样本上"价格反推 vs 台账"**零分歧**（40 只 ST / 1 只两侧均非 ST） | 方向正确 |
| 票日级 | 有假阳性：`000909` 26 命中 / 21 真 / 5 假；`000838` 20/17/3；`002227` 10/8/2 | **精确率 ≈0.8 量级，不是 1** |

⇒ 结论级别只能是"**方向正确、逐行有百分之十几误判**"，41 只/2,974 票日的样本量不支持更细的话。
这也解释了 §5 为什么把三档并报：`regime5` 的 5.8% 上沿附近正是误判集中区。

**因此修复路径写成四层合并**（不是"换成通达信源"这么一句话）：

1. **F10 台账**（带日期；条目数不均，实测分布 `0:4739 / 1:182 / 2:233 / 3:60 / 4:11 / 5:4`、
   只有 490 只有事件 ⇒ 覆盖面上限由"有没有这一栏"决定，不是"每票几条"）⇒ 有栏票的相应段可权威判定；
2. **`block_gn.dat`**（当日成员，1.9s 全量）⇒ 定"今天谁是 ST"，与 `all_a_stocks.json` 需先取权威；
3. **akshare 深市带日期改名面板**（依赖已在 `requirements.lock`）⇒ 补沪市缺口；
4. **价格反推**（本快照的 `regime5`）⇒ **只用于三者都覆盖不到的早期段，并且显式标为推断而非权威**。
   按 §3.3.5，"早期段"指的是现役票在**台账盖不到的那一段**（整栏「暂无数据」的 90.63%，
   或有栏票最早一条实施日期——F10 侧全局最早 2014-08-06——之前）的历史，**不是退市票**（退市票不在训练宇宙里）。

### 3.4 为什么今天的链没有算错（算术结论，条件是三条）

并轨后 ST 主板档 = 10% = 普通主板档，所以 `get_limit(code)`（无日期 ⇒ 用当前档）对
**日期 ≥ 2026-07-06 的行**返回的就是正确阈值。这条"恰好正确"要同时满足三个条件，任何一条变化
都会让它在生产路径上失效，后人别把它当永久安全：

1. 并轨后 ST 主板与普通主板同档（`LIMIT_RATIO_ST_MAIN == LIMIT_RATIO[MARKET_MAIN]`）；
2. 推理时的行日期不早于并轨日；
3. 调用方只碰主板。双创/北交所不受此次并轨影响，但第 1 条只对主板成立——**主板 ST 之外
   没有任何一档被这次规则变更救回来**。

### 3.5 样本枚举的一条坑：指数文件与个股同码

`data/parquet/daily/` 里指数与个股共用命名规则，去掉交易所前缀后**同一个 6 位码指向两只标的**：
`sh000001` 是上证指数、`sz000001` 是平安银行。而 `market_of()` 只看数字段（`000001` → 主板），
所以按 `strip_exchange_prefix(fp.stem)` 枚举日线文件时，8 个指数序列会被当成 8 只主板个股进样本。
仓库别处已把这条记成已知危害（`tdxfeed/freshness.py:270`、`tdxfeed/adjusted.py:7`、
`tdxfeed/daban/limit_price.py:38`）。

本脚本首版**没有排除**，实测影响（两次全市场跑的差值）：

| 量 | 未排除 | 排除后 | 差 |
|---|---:|---:|---:|
| 票数 | 5,229 | **5,221** | −8 |
| 样本行 | 16,772,057 | 16,763,761 | −8,296 |
| 主板行 | 13,133,359 | 13,125,063 | −8,296 |
| 现役 y=1（主板） | 206,272 | 206,261 | −11 |
| 5% 档天数 / 并轨前 | 740,203 / 729,564 | 740,111 / 729,558 | −92 / −6 |

| 翻转（loose） | 79,507 | 79,499 | −8 |

8 个在场指数文件各 1,042 行（只同步了近 4.3 年，不是全历史），合计有效行 8,296，与差值逐行对上。
**中心档的翻转数没有变**，所以这条坑没有污染本轮的头等结论；但它污染了基准率与分母，
并且让自校验的 ST 观察数出现 145 vs 名单 144 的错位（`sh000016` 上证50 被当作 ST 个股 000016 计了一次）——

## 4. 污染面量化（全市场，`--full`，中心档 medium）

## 7. 形状证据：翻转发生的地方正好钉在 5.00% 上

如果翻转是真的"触到 5% 涨停价"，翻转行的前向收益应当在 0.050 附近堆成一个尖，而不是一片平坡。
`shape --sample 400`（主板票随机抽 400 只，medium 档）：

```

  [0.043,0.045)     224  ###
  [0.045,0.047)     442  ######
  [0.047,0.049)     701  ##########
  [0.049,0.051)   3,932  ############################################################
  [0.051,0.053)     544  ########
  [0.053,0.055)     137  ##
  [0.055,0.057)      89  #

对照：现役正样本落在 [0.094,0.1] 钉子内 = 45.0%（中位=0.1000 p95=0.1010）
主动排除（不参与任何计数）: {'index_symbol': 8}
```

- **58.0% 的翻转行落在 `[0.049,0.051)`**（3,932/6,777），中位数恰是 0.0500，p25–p75 =
  0.0493–0.0508。一只票涨到 5.00% 就再也涨不上去，只可能是被涨停价钉住 ⇒ 这条支持"翻转是真涨停被漏记"，

所以这一节的分母（6,777）与上一版（7,795）不同——两版的尖峰占比（58.0% / 57.7%）一致。

## 8. 判据自校验：并轨日必须出现"同步解锁"

规则变更是唯一能让**一批票在同一日**从 5% 档切到 10% 档的原因。medium 档的自校验（同一次扫描内）：

```
当前名 ST 的主板票: 观察 144 只，其中并轨前 40 日全程 regime5 且并轨后解除 = 8 只（5.6%）
当前非 ST 的主板票: 观察 3,041 只，其中并轨前 40 日全程 regime5 且并轨后解除 = 2 只（0.1%）
```

ST 组的解锁率是对照组的 **84 倍**（(8/144)/(2/3,041)）：判据抓到的"解锁"确实集中在 ST 组，
不是全体涨停票的普涨假象。绝对数是 8 与 2，这个比值本身不稳，只用来说明判据的方向。
144/3,041 是"有 ≥40 个并轨前交易日且并轨后有数据"的主板票；与 §3.3 的 rule 子命令入口不同
（那里是名单里全部 144 只 ST + 随机 144 只对照），两边的数不可直接互比。
**2026-11-06 名单刷新后同一判据读作 142 / 3,043 ⇒ `(8/142)/(2/3,043) ≈ 85.7 倍`**：分子没动，
变的只有两个分母，而**这两个分母是名单侧的数**（`_scan` 的 `st_now` 取当日名称）⇒ 引用它们要认日期。
同一趟扫描的污染量四数（票数 5,222 / 可判样本行 16,768,995 / 现役 y=1 216,826 / 中心档翻转
**52,919 逐值不变**）与逐项归因见 `docs/research/2026-11-06-universe-refresh-impact.md`。
（那里是名单里全部 144 只 ST + 随机 144 只对照），两边的数不可直接互比。
**排除指数文件前这里是 145/3,048**——多出来的 1 只就是被当成个股 000016 的上证50 指数（§3.5）。
8/144 这个绝对值小，原因同 §3.3——今日 ST 名单与历史 ST 状态不重叠，
**这个数不该被读成"只有 5.6% 的票被影响"**，它是判据特异性的检验，不是覆盖率。

### 9.1 哪些是推断、推到什么程度

| 结论 | 性质 | 若判据错会怎样 |
|---|---|---|
| `limit` 维无 5% 档、`is_st`/`is_bj` 常数列 | **事实**（直接读模型产物头） | 不受本轮判据影响 |

## 10. 上一轮的双跑与位移数为什么仍然成立

本轮的发现会动摇"绝对命中率"，不会动摇"两个产物谁更好"的比较，因为它们吃的是**同一套漏标**：

- **`docs/research/2026-10-30-hfq-read-authority-dual-run.md`（hfq vs raw）**：两臂共用

### 13.3 读数与判据（先定判据再看数）

> **决定"重训值不值得"的核心量是两个占比，不是行数**：面板（权威三层并读）能解释污染面的

### 14.5 本批自己走错并修掉的一步：新开关的 help 串让训练入口当场炸

`--include-inferred` 的 help 里写了裸 `96.4%`。Python 3.14 的 argparse 在 **`add_argument` 当场**
校验 help 串并抛 `ValueError: badly formed help string`，于是训练入口连 `--help` 都跑不起来
（实测 `TDX_OUT_ROOT=/tmp/… scripts/train_daban_model.py --limit 1` 退出码 1，栈顶在 argparse）。
写完后定向套件 38 条**全绿**——因为没有任何用例真的构造过 `main()` 的 parser
（`_train_mod()` 用 `spec_from_file_location` 只 import 模块，不进 `main()`）。

补了 `test_train_entry_argparse_actually_builds`：真跑一次 `--help` 子进程冒烟
（`--help` 在 `parse_args` 就 short-circuit，不读盘、不写产物，所以对在役入口是安全的），
断言退出码 0 且 `--include-inferred` 出现在 help 里。红绿都验过：把 `%%` 改回裸 `%` 立刻
exit 1，改回来 exit 0。**教训不是"要转义百分号"，是"给生产入口加 CLI 参数就必须真跑一次它的
CLI"**——只 import 模块的用例覆盖不到 argparse 这一层。
