## 2. 盘中扫描

```bash
# 单次扫描（建议 09:30–10:00）
venv/bin/python scripts/daban_scan.py --top 20

# 指定市场环境（影响仓位档位与打分中的环境分）
venv/bin/python scripts/daban_scan.py --phase 启动期

# 持续盯盘（默认 3s 一轮），实时跟踪封板 / 炸板 / 回封
venv/bin/python scripts/daban_scan.py --watch --interval 3

# 传入流通股本 → 启用金额法封单比（封单额/流通市值）
venv/bin/python scripts/daban_scan.py --float-shares data/daban/float_shares.csv
```

产物：

```
data/daban/scan_<日期>_<时分秒>.csv      全部候选明细（含 reasons 说明）
data/daban/candidates_<日期>.blk         通达信"明日候选"板块（每行一个 sh/sz/bj 代码）
data/signals/market_phase_<日期>.json    市场环境 + 仓位参数
```

`.blk` 导入：复制到通达信 `T0002/blocknew/` → 软件内板块管理刷新。

### 封单比口径（重要）

计划书 §2.6 定义了两个封单比口径，本程序的实际取法：

| 口径 | 定义 | 本程序 |
|---|---|---|
| 金额法 | 封单额 / 流通市值 | ✅ 需 `--float-shares` 传流通股本 |
| 股数法 | 封单股数 / 当日成交量 | ⚠️ **降级**：新浪新版接口不返回当日成交量，改用 `封单股数 / 近5日均量` 作代理 |

**量纲不同，不能直接套用 §2.6 的绝对档位阈值**：

- 有流通股本 → 封单分按 §2.6 绝对档位（极弱/弱/正常偏强/强/极强）
- 无流通股本 → 封单分按候选集内**相对分位**（仅用于排序，不下绝对强弱结论）

真实封单比（含撤单率、封单队列）仍需 L2，见计划书附录 E。

## 3. 回测

```bash
# 实盘打板口径：T 日收盘封死涨停 → 以涨停价买入 → T+1 开盘卖出
venv/bin/python scripts/daban_backtest.py --start 20200101 --end 20261019 --mode limit

# 接力口径：T+1 开盘买入 → 止盈/止损/超时
venv/bin/python scripts/daban_backtest.py --mode chase --tp 0.30 --sl 0.10 --hold 5

# 资金容量约束：每天最多打 20 只（同日优先连板高度高的）
venv/bin/python scripts/daban_backtest.py --mode limit --daily-cap 20
```

### 实测结果（2020-01-01 ~ 2026-10-19，5,565 只，NET 双边成本 0.30%；当时含北交所 344 只，北交所数据已于 2026-10-21 下线）

`--mode limit`（涨停价买 / T+1 开盘卖）：

| 指标 | 全样本 | 2020 | 2021 | 2022 | 2023 | 2024 | 2025 | 2026 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 样本数 | 90778 | 10594 | 14299 | 13599 | 8097 | 15837 | 14560 | 13792 |
| 胜率% | 62.5 | 66.1 | 65.3 | 62.4 | 61.4 | 65.6 | 59.8 | 57.1 |
| 平均收益% | +1.62 | +1.70 | +1.54 | +1.44 | +1.56 | +2.30 | +1.53 | +1.16 |
| 平均盈利% | +3.73 | | | | | | | |
| 平均亏损% | −1.92 | | | | | | | |
| 盈亏比 | 1.95 | 1.84 | 1.86 | 1.76 | 1.97 | 2.16 | 2.03 | 1.88 |

- 日频等权资金曲线（每日 ≤20 只口径）：最大回撤 −7.78%，日均 +1.52%
- **7 年全部为正**，2024 最强（+2.30%/笔），2026 边际走弱（+1.16%/笔，胜率 57.1%）
- 剔除异常样本 2157 笔（除权未补偿/数据越界），占 2.3%

### 打板 vs 追高：同一批标的的期望差 ≈ 3.8 个百分点

同一份数据、同一成本，两种入场方式（2026 年窗口）：

| 入场方式 | 口径 | 样本 | 胜率% | 平均收益% | 盈亏比 |
|---|---|---:|---:|---:|---:|
| **封板价买入** | T 日涨停价买 → T+1 开盘卖 | 13792 | **57.1** | **+1.16** | 1.88 |
| **次日追高** | T+1 开盘买 → 止盈/止损/持有 5 日 | 12725 | 36.0 | **−2.14** | 0.97 |

**结论：溢价产生在"封板那一刻"，次日追高不但吃不到溢价，还要倒贴 3.8 个百分点。**

这与计划书 §D.3 的方案 E（+3.13%/笔，且带 T+1 涨幅≥9.5% + 量比≥1.5 强过滤）互相印证：
过滤掉的正是最差的追高样本 —— **过滤器贡献了约 5 个百分点的期望差**，与 §D.3.1「v2 过滤器已榨干翻倍事件的可观测信息」的判断一致。

实盘含义（§3.2 买点优先级）：
- 能封板时在**涨停价**成交，是唯一正期望的入场方式
- 追高、等回封后再进，期望被大幅稀释；回封买点只有在板块同步加强时才成立

### 这个数字该怎么读

✅ 可信：单笔期望、胜率、盈亏比、分年稳定性 —— 与"打板隔夜溢价约 1–2%"的民间经验吻合。

⚠️ 不可直接当实盘预期：

1. **假设每笔都成交在涨停价**：尾盘偷袭、一字板、T+1 集合竞价卖不出好价等摩擦未建模
2. **组合年化不可信**：日均等权满仓的年化会高到荒谬（数学上成立，实盘做不到），只看逐笔期望
3. **未做板块/地位过滤**：这是"全市场打板"的基准线，加入 §2 六标准过滤后才是你的策略
4. **无容量约束的边界**：单只 1/20 仓位意味着要同时覆盖 20 只涨停股的资金

## 4. 口径与坑位备忘

| 项 | 说明 |
|---|---|
| 涨停价 | 前收盘 × (1+比例) **四舍五入到分**；主板 10% / 双创 20% / 北交所 30% / 主板 ST 5% |
| 与 `features_5d.get_limit` | 后者是 0.095/0.195/0.295 的浮点缓冲口径（用于回测特征），**不可用于盘中挂单价** |
| `data/parquet/daily` 的 date 列 | 存在 `int64(YYYYMMDD)` 与 `date32` 两种 schema 漂移 → 必须走 `tdxfeed.date_utils.parse_date_series`，否则全量落到 1970 年 |
| 日线文件名 | 带交易所前缀（`sh600000.parquet`），股票池代码是 6 位无前缀 → 用 `daily_path()` 定位 |
| 日线 close 口径 | **raw 价**（未复权），除权日需用 `data/adj_factor/` 补偿，否则 T+1 开盘断崖被误判为巨亏 |
| 新浪字段 | 新版布局：`[8]` 委买一量=封单股数、`[9]` 委买一额=封单金额、`[30]/[31]` 日期时间；旧版已做兼容 |
| 回撤计算 | 9 万笔样本逐笔复利会下溢 → 必须用**日频等权**曲线 + 对数累计 |

## 5. 新增能力（2026-10-20 第二批）

### 5.1 板块强度 Sec 因子（§A.1）

```python
Sec = 40×板块涨幅排名百分位 + 40×min(板块涨停数,10)/10 + 20×领涨股涨幅/10
```

- 成分股分组：`data/industry/sw_stock_industry.csv`（申万行业 333 个，5931 只，**本地已有，零外部依赖**）
- 涨幅/涨停：新浪 L1 全市场快照（扫描器本来就拉全市场，板块强度是副产品）
- 板块涨幅取**成分股涨幅中位数**（抗极值），领涨股 10% 封顶 → Sec ∈ [0,100]
- 集成到 §A.2 打分：`0.22×封单 + 0.15×换手 + 0.30×Sec + 0.18×状态 + 0.10×身位 + 0.05×环境`
- **行业名当前显示为行业代码**（申万在线接口 `sw_index_third_info/cons` 现整体不可用，页面解析失败）。
  接口恢复后跑 `scripts/daban_sector_loader.py` 生成 `data/industry/sector_name.csv` 即可显示中文名（Sec 计算不受影响）

### 5.2 量化初筛闭环（§D.5）

```bash
# predict.py TopN 作候选池 + 盘口确认
venv/bin/python scripts/daban_scan.py --pool predict --pool-top 50
# 其他池
--pool file:<csv>     # 第一列 6 位代码
--pool block:<blk>    # 通达信板块文件
```

⚠ `predict` 池按**文件名内嵌时间戳**取最新（不能用字典序：`predict_top5_20261020`
会输给 `predict_top6_20261010`）。

### 5.3 真实封单比（附录 E M1）

```bash
venv/bin/python scripts/daban_scan.py --seal-export data/daban/tdx_seal_20261020.csv
```

- 通达信公式导出 CSV → `seal_ratio.load_tdx_export()` 解析，列名兼容中英文：
  `代码/名称/委买一量/委买一额/流通市值/成交量/现价/涨停价/时间`
- 外部源的封单量/额/流通市值/成交量**优先于** L1 快照
- 有了流通市值 → 启用**金额法**（封单额/流通市值，§2.6 主推口径）
  → 实测样例：星光股份 68.7%（极强）、京城股份 54.8%（极强）
- L2 接入留了协议 `SealRatioSource.fetch(codes)`，实现即可替换

### 5.4 封单衰减 / 撤单速率

- 扫描器维护每只股票的封单时间序列 → 输出 `cancel_rate`（万股/分钟）
- `--watch` 模式下对撤单加速（>200 万股/分）的标的单独告警
- ⚠ 这是**封单量下降速度**的代理，不是真实撤单率（真实撤单率需 L2 委托队列）

### 5.5 竞价阶段（§3.2）

`tdxfeed/daban/session.py` 判定交易时段：
`pre_auction / auction(09:15-09:25) / pre_open / continuous / lunch_break / closed`

- 竞价期新浪返回的现价 = **虚拟开盘价**，封单量 = **未撮合买量**
- 状态新增：`竞价封板`（虚拟开盘即涨停）、`竞价高开`（高开 ≥5%）
- 09:15–09:20 委托可撤 → 竞价封单要在 09:20 后再确认一次

### 5.6 下单接口（§C.4）

```bash
# 落盘信号单（不真实下单，人工复核后手工下单）
venv/bin/python scripts/daban_scan.py --broker dryrun --cash 300000 \
    --max-single-pct 0.15 --max-total-pct 0.50 --stop-loss 0.05 --take-profit 0.10
```

- 产出 `data/daban/orders/orders_*.csv|json` + **通达信条件单文本**（可直接粘进券商条件单）
- 仓位规则按 §5.1/§5.2/§6.2：单票上限、总仓上限、最小交易单位、单笔最小金额
- `QmtBroker`（miniQMT/xtquant）已实现骨架，仅支持 Windows 券商环境；本机 Linux 会明确报错并提示改用 dryrun
- ⚠ 本模块**不做自动风控**，止损/仓位必须显式传参

## 7. 第三批能力（2026-10-20 续做）

### 7.1 真实封单比彻底自动化（双源：新浪 + 腾讯）

新浪 L1 给封单（委买一量/额）但**不返回成交量/流通市值**；腾讯 `qt.gtimg.cn` 补齐：
`成交量(手) / 成交额(万) / 换手率 / 流通市值(亿) / 量比 / 交易所涨停价`。

| 指标 | 来源 | 覆盖 |
|---|---|---|
| 封单股数/金额 | 新浪 L1 | 100% |
| 当日成交量 | 腾讯 | 100% |
| 流通市值 | 腾讯 | 100% |
| 换手率（§A.1 因子 T） | 腾讯 | 100% |
| 量比 | 腾讯 | 100% |
| 涨停价交叉校验 | 腾讯[47] vs 自算 | 自动，差异 >0.011 元会在 reasons 报警 |

**结论：金额法封单比（封单额/流通市值，§2.6 主推口径）现在全自动，无需人工从通达信导出。**
实测：京城股份 11.1%（强）、吉大正元 23.7%（极强），换手 8.7%~19.7%。

```bash

venv/bin/python scripts/daban_scan.py --top 20
```

## 8. Sec 消融实验：板块过滤到底值多少（2026-10-20，零重训成本）

脚本：`scripts/daban_sec_ablation.py`（join 打板回测明细 90,778 笔 + 板块特征 89,474 笔，命中 98.6%）

### 8.1 单因子：Sec 四分位（单调递增 ✓）

| 组 | 样本 | 胜率% | 均收益% | 盈亏比 |

### 8.6 对"要不要重训"的结论

Sec 的增益已被**推理期过滤**吃掉（+0.37pp/笔），把它再塞进模型作为特征，边际收益很小
