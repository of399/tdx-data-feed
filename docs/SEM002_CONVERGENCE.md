## 1. 统一改造模式

每处"未 raise、也无计数动作"的 `except` handler：

```python
# 文件头（模块级）
from collections import Counter

# 吞错计数（SEM002）：每处被吞掉的错误都计入统计，按函数名分桶，便于事后追溯失败率
_ERROR_COUNT = Counter()


def fetch_one(code):
    try:
        return _get(code)
    except Exception as e:            # 原来只有 logger.exception(e)
        _ERROR_COUNT['fetch_one'] += 1
        logger.exception(e)
```

| 规则 | 说明 |
|---|---|
| 计数插在 **handler 体第一行** | 无论后面走 `return` / `continue` / `break` 还是别的路径，都会计数 |
| 体只有 `pass` → 直接替换为计数语句 | 语义等价（都是 no-op），不改变控制流 |
| 计数键 = **所在函数名** | 定位"哪个函数在悄悄吞错"；模块级用 `<module>` |
| 每文件一个 `Counter` | `collections` 是标准库 → **零导入路径风险**（`scripts/` 下部分脚本没把仓库根放进 `sys.path`，引项目内模块会在某些调用方式下 ImportError）|

### 为什么不直接 `raise` 或 `return` 错误结构

349 处里 255 处是"返回错误结构/默认值"（例如 MCP server 返回 JSON-RPC error 对象、采集脚本回退到内置样例）。这类**错误已外传给调用方**，不是"静默消失"，强制改成 `raise` 会改变对外契约（尤其 MCP 协议响应）。因此统一选择"**外显 + 计数**"：错误仍然按原契约返回，同时留下一份可统计的失败计数。
