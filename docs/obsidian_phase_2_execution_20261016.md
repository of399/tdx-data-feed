## 3. 校验器设计要点

### 3.1 模块分类（按顶层目录）
`01-标的`/`02-框架`/`03-数据`(豁免)/`04-回测`/`05-知识库`(含数学)/`06-模板`(豁免)/`07-日记`(豁免)/`00-收件箱`(豁免)。

### 3.2 元数据校验
- 强校验模块必填 `tags`/`创建日期`/`状态`/`模板`；数学笔记必填 `title`/`type`/`domain`/`level`/`status`/`tags`/`created`
- 日期格式 `YYYY-MM-DD`；`tags` 须非空列表；数学笔记须含 `math-notes`
- 标的前缀 `^\d{6}-名称.md$` + 按代码去重（全/半角 `A`/`Ａ` 计同码）
- MOC/总览类 landing 页豁免

### 3.3 链接校验
- **先剥离代码块**（围栏 ``` + 行内 `` ` ``）避免 Python 列表 `[[a,b]]` 误匹配
- wikilink 解析：去 alias(`|`)/标题(`#`)/块(`^`)
- 日期链接 `[[YYYY-MM-DD]]` → `07-日记/<date>.md`，缺失记为**软缺失**（Obsidian 按需创建，非硬错误）
- 笔记名链接 → 按 basename 查索引，缺失为**硬断链**
- depends 图：`note → target`，DFS 三色检测循环依赖；自引用不计环

### 3.4 边界处理（已实现）
无 frontmatter、YAML 解析失败、空值、日期格式错、tags 非法、别名/标题冗余、同笔记重复链接、链接自指、日期笔记缺失 — 均有明确处理路径。

## 6. 退出码约定
- `verify-obsidian-metadata`：0=无错误(允许警告) / 1=字段/格式/重复错误 / 2=参数依赖错

## 7. 风险与应对
| 风险 | 应对 |
|---|---|
| 校验器误报（代码块 `[[...]]`）| 提取链接前剥离围栏/行内代码块 |
| 日期链接被当断链 | 单列「软缺失」，不计入硬错误 |
| 自动建空笔记污染知识库 | 仅建 `v4模型.md`（模板显式引用、意图明确）；概念笔记交用户写真内容 |
| MOC/总览 landing 页被 schema 误伤 | 文件名豁免规则 |
| 写操作审批超时 | 创建笔记走 Python 脚本（非 execute_command 直写）|
