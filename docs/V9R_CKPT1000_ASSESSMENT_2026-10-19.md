- 评估对象：`train/output/qwen3-14b-tdx-v9r/checkpoint-1000`
- 评估方式：`run_v4_eval.py --quantize-8bit --limit 120`（8bit 双卡，1691.4s）

## 0. 结论

> **ckpt-1000 仍然失败（mode collapse），但比 ckpt-800 略有改善。**
> **建议保留而非删除** —— 体积仅 384M，且是"4 项修复无效"的关键证据链。

## 2. ckpt-1000 评估结果（直接证据）

```
方向准确率 = 0.0333    格式遵循率 = 1.0000    解析失败率 = 0.0000
spearman   = 0.0000
cls_acc    = up:0.0500  down:0.0000  flat:0.0000
stream 100 : up=9  down=0  flat=91  none=0
```

### 2.1 横向对比

| 模型 | direction_acc | flat 占比 | spearman | 判定 |
|---|---:|---:|---:|---|
| v9（失败基线）| 0.0202 | 100% | — | 坍缩 |
| v9r **ckpt-800** | 0.0085 | 96% | 0.0000 | 坍缩 |
| **v9r ckpt-1000** | **0.0333** | **91%** | **0.0000** | **仍坍缩** |
| sanity 阈值 | 0.20 | — | — | — |

### 2.2 关键解读

1. **略有改善，但不改变性质**：direction_acc 从 0.0085 → 0.0333（约 4 倍），up 预测从 2 → 9。
   但这是"从完全死到偶尔动一下"，**距离 0.20 阈值仍差 6 倍**。
2. **`spearman = 0.0000` 是最强证据**：模型输出与真实收益**完全无单调关系** —— 即使个别方向猜对，也不具备排序/预测能力。
3. **`down = 0`**：120 条中从不预测下跌；`flat` 仍占 91%。
4. **loss 曲线早已平坦**：step 500（0.1497）→ step 1100（0.1388），**600 步 / 约 11 小时，loss 仅降 0.011** —— 模型在 step 500 前就已收敛到退化解，后续训练无意义。

### 2.3 为什么"更多步数"救不了它

mode collapse 是**训练动力学失败**（模型退化为输出先验最高的多数类），不是"训练不够"。
证据：v9 训练 1600 步 loss 同样停在 0.13-0.15；v9r 从 500 到 1100 步 loss 平坦。
**继续训到 2000 步不会改变结局** —— 这也是当时及时止损的合理性所在。

## 3. 保留还是删除：建议**保留**

### 3.1 理由

| # | 理由 |
|---|---|
| 1 | **体积小**：384M/个，v9r 目录共 1.2G。相比 `models/`（30G）与 `train/output/` 其他实验（合计 8.0G），删除它释放空间有限，**不值得为此丢失证据** |
| 2 | **审计价值**：构成完整失败证据链 —— v9（0.0202）→ v9r ckpt-800（0.0085）→ v9r ckpt-1000（0.0333），证明「4 项修复（thinking false / rank8 / cutoff1280 / packing off）叠加无效」 |
| 3 | **未来实验基线**：若有人验证「`enable_thinking: true` 才是正确方向」（R10 实验曾显示 think 0.0682 > no-think 0.0202），需要一个 no-think 失败基线作对照 |
| 4 | **不可复现**：重跑需 20h+，且 v9r 配置已归档。删除后该实验无法复现 |
| 5 | **无自动加载风险**：模型不会被任何流程自动加载（`MODEL_REGISTRY` 不含 LLM；实盘主力是 LightGBM）|

### 3.2 建议动作（替代删除）

| 动作 | 说明 |
|---|---|
| **打标记** | 在 v9r 目录加 `FAILED_DO_NOT_USE.md`，写明 ckpt-1000/800/200 的评估结果与失败模式 |
| **可删 ckpt-200** | 价值最低（step 200 必然更差），若确需省空间，优先删它（省 384M）|
| **不建议删 ckpt-1000** | 它是"训练更久是否改善"这一问题的**直接答案**（0.0333，仍是 spearman=0）|

## 4. LLM 训练 vs daban 重训：全维度对比

| 维度 | **v9r（LLM）** | **daban（LightGBM）** |
|---|---|---|
| **目标** | 3 分类方向预测（涨/跌/震）→ `direction_acc` | 2 分类次日收盘涨停概率 → `OOS AUC` |
| **算法/基座** | Qwen3-14B + LoRA（rank 8，7 个 target 模块）| LightGBM GBDT，从零训练 |
| **输入表示** | 文本序列（K 线序列化为 token，`cutoff_len=1280`）| 29 维数值特征向量 |
| **训练数据** | `tdx_v8_train.jsonl` **33,274 条**文本样本（20MB）| **1,181,119 条**表格样本（全面板剔除不可交易）|
| **样本量级** | 3.3 万 | 118 万（**36 倍**）|
| **有效 batch** | `bs=1 × grad_accum=16` = 16 | 全量（`scale_pos_weight=5.1`）|
| **训练流程** | llamafactory SFT → 每 200 步存 ckpt → `run_v4_eval.py` 单独评估 | `build_dataset → train → 报告` 一次完成 |
| **硬件资源** | **双 GPU 100%**（各 ~2.5GB 显存）+ CPU 数据加载 | **CPU only**（LightGBM 多线程），~3GB 内存 |
| **耗时** | **20h25m** 到 step 1100/2000（全程预计 36h+）| **17-19 min** 全程 |
| **单次产出** | adapter **384M**/ckpt | 模型 **1.76MB** |
| **评估成本** | 8bit 加载 + 120 条推理 ≈ **28 min** | 秒级（全市场 predict 40s）|
| **迭代周期** | **天级**（训练 20h+ + 评估 30min）| **分钟级**（17min 训练）|
| **当前结果** | direction_acc **0.0333**（91% flat，spearman 0）| AUC **0.7478**，Top5 命中率 **21.7~24.5%** |
| **实盘状态** | 未部署，**已止损** | **已切流 `DEFAULT_MODEL`**（小仓位场景）|
| **失败模式** | mode collapse（退化为输出多数类）| 无（需监控 AUC 衰减）|
| **回退成本** | 丢弃 20h+ | 重训 17min |

### 4.1 核心差异（三条）

1. **数据规模差 36 倍**：LLM 3.3 万文本样本 vs daban 118 万表格样本。对于"次日是否涨停"这种**低信噪比任务**，样本量是决定性因素之一。
2. **迭代速度差约 60 倍**：17min vs 20h+。daban 可在一下午内完成"诊断→改造→重训→对比"全链；LLM 一次实验就要一天。
3. **结果差距**：LLM 连续两代 mode collapse（v9 0.0202 → v9r 0.0333，均 spearman=0）；daban 一次达到 AUC 0.7478 且分年度稳定。

## 5. 明确结论

| 问题 | 结论 |
|---|---|
| ckpt-1000 是否存在问题 | ✅ **是** —— direction_acc 0.0333（阈值 0.20 的 1/6）、91% flat、**spearman = 0** |
| 是否应保留 | ✅ **保留**（384M，证据链价值 > 空间价值）；建议加 `FAILED_DO_NOT_USE.md` 标记 |
| 是否应删除 | ❌ **不建议**；若确需省空间，优先删 ckpt-200（价值最低）|
| LLM 路线是否继续 | ❌ **不建议** —— 连续两代坍缩 + spearman=0 + 迭代慢 60 倍；应转投 LightGBM 路线 |
| daban 路线 | ✅ **继续** —— 已切流小仓位，重点转向实盘可执行性验证（成交率/滑点/隔夜跳空）|
