# 工作空间重跑方案（分层 + 风险分级）

- 日期：2026-10-19
- 触发：用户要求「重新运行整个工作空间，从头开始执行，不沿用已有进度或中间状态」
- 状态：L0/L1 已执行完成；L2-L6 待用户确认范围

---

## 0. 关键澄清：本项目**没有**「整个工作空间一键重跑」的入口

`Makefile` 有 97 个 targets，但**不存在 `run-all` / `pipeline` 之类的统一入口**。工作空间是**多阶段流水线**，各阶段输入输出耦合：

```
[L5 数据同步] → parquet ─┬→ [L2 特征/诊断] ─┐
                         ├→ [L3 模型重训] ─┼→ [L4 预测] → [监控/回测]
                         └→ [L6 LLM 训练] ─┘
```

因此「重新运行整个工作空间」必须**分层定义**，不能一概而论。

---

## 1. 「不沿用已有进度或中间状态」的风险评估（不可逆项）

| 资产 | 规模 | 若清零 | 建议 |
|---|---:|---|---|
| `data/parquet/daily` | 1.2G | 需重新全市场同步（**数小时**），且历史行情可能已不可复得 | ❌ **不清** |
| `models/` | 30G | 含 Qwen3-14B 基座，重新下载不现实 | ❌ **不清** |
| `train/output/` | 9.2G | 含 **v9r checkpoint-1000/800/200**（约 17h 训练成果）| ❌ **不清** |
| `data/double_up/` | 404M | 含 daban 生产模型（刚切流为 DEFAULT_MODEL）| ❌ **不清** |
| `__pycache__` / `.pytest_cache` | 小 | 无影响 | ✅ **可清** |
| 临时日志 `logs/*.log` | 中 | 部分为审计证据，建议保留 | ⚠️ **选择性清** |

**结论**：无条件「清空重跑」会导致数小时至数天的成果丢失且部分不可恢复。**本方案采用「可复现性重跑」而非「清空重来」**——用现有输入重新执行各阶段，验证结果一致性。

## 3. 环境初始化要求

### 3.1 应当做的（零风险）

```bash
# 清理字节码缓存（不影响任何产物）
find . -name "__pycache__" -type d -not -path "./venv/*" -exec rm -rf {} + 2>/dev/null
rm -rf .pytest_cache .ruff_cache
```

### 3.2 不应当做的（不可逆）

- ❌ 删除/清空 `data/parquet/`、`models/`、`train/output/`、`data/double_up/`
- ❌ `make update`（会改变依赖版本，破坏 `requirements.lock` 锁定）
- ❌ 停止 12 个 systemd timer（`tdxfeed-sync`/`predict-daily`/`canary-health` 等）

### 3.3 依赖加载

**无需重新安装**：`requirements.lock`（4685 字节）已锁定精确版本，`venv/` 完好。
仅在以下情况才需重装：
- 用户显式要求「全新环境」
- `pip check` 报告冲突（当前仅 mootdx-httpx 声明性冲突，功能正常）
