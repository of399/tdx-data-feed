# 回测结论出厂自检

这个项目的教训不是"算错了"，而是**算出来的东西系统性偏乐观**。四条口径都朝同一个方向错，
所以它们在代码里已经固定住了，不要再重新讨论，只会在有人违反时纠正。

## 触发后先做的一件事

在报出任何数字之前，先跑下面这条 grep（便宜、能在 30 秒内证伪"结论没问题"这个前提）：

```bash
grep -rnE 'H₀\s*=\s*50|胜率.*显著.*50|显著异于 50' --include='*.py' --include='*.md' \
  --exclude-dir=data --exclude-dir=_archive . | grep -v '^./.qoder/skills/'
```

命中**不等于**违反，三类要分开：负向断言（`tests/test_plan_e_significance.py` 里
`assert "H₀=50%" not in md` 是闸门）、纠正性措辞（`AGENTS.md` 那条约定本身、以及
`docs/math_upgrade_plan_20261015.md` 里已带「2026-10-24 更正：原假设不是 50%」的句子），
以及真违反。库里目前只剩一处真违反：
`docs/P0_1_ACCEPTANCE_REPORT_2026-10-16.md` 把「胜率 H₀=50% p=0.001 ⇒ 显著」写成结论，
而全文没有标注它是旧口径。引用那份报告前先按本 skill 纠正，不要当项目标准。

## 口径 1：Deflated Sharpe 的输入必须是周期内 Sharpe，不是年化

方差项是 `(1 − γ₃·SR + …) / T`，T 是**观测数**。年化值直接喂进去会把 z 放大 √252 倍，
一个 Sharpe 0.08 的策略会打印成 "p=0.010 显著"。

- 年化值只能经过 `dsr_p_from_annual_sharpe` 换算后再进 DSR；
  `plan_e_backtest.summarize` 和 `quant/multifactor/engine` 两个调用点共用这个函数。
- 只在年化 Sharpe **为正**时这个 bug 才造假阳性；负值本来被钳在 p=1.0，
  所以历史上那批 `data/plan_e/plan_e_backtest_mf_v1_*.md` 没有错误结论，只有陈旧数字。
  审计陈旧产物时先判断它带的是**哪一种**缺陷，再决定要不要处理。份数随定时任务变，
  别拿数字当核对依据——`data/` 不入库，只有这台机器上有。

## 口径 2：置换检验测的是"净值曲线被平滑了"，不是择时能力

`permutation_return_test` 的默认统计量是 lag-1 自相关（均值和 Sharpe 对置换是不变的，
换过去结果一模一样）。净值曲线把每笔盈亏摊到 `hold` 个连续交易日上，重叠持仓**机械地**
造出自相关。所以 p 很小只说明曲线是平滑的，永远不能读成 timing skill。

## 口径 3：胜率的零假设是赔付结构隐含的盈亏平衡胜率，不是 50%

`breakeven_win_rate(avg_win, avg_loss) = |avg_loss| / (avg_win + |avg_loss|)`。
TP+30% / SL−10% 的梯子会把任何零边际的策略压到 50% 以下很远，所以"显著不等于 50%"
是关于赔付结构的同义反复——它曾经是报告里唯一一行"显著"。

- 对的比法（112 笔样本）：33.9% vs 31.2% ⇒ 单侧 **p=0.296**。
- 50% 这个零假设同时还是失灵的另一头：利润因子 2.21 时，真有 50% 胜率反而打 p≈1.0。

## 口径 4：随机择时基线已经做了，它的 p 只是条件推断

`plan_e_backtest.py --random-timing-trials N`（默认 300，`0` 跳过）：固定股票池，每笔只在该股
真实 `entry_date` 区间内随机抽一个入场日，再用**同一个** `_settle_from_entry` 跑同一个出场梯子。
出场梯子必须共用，否则比较没有意义——`tests/test_plan_e_random_timing.py` 的等价性测试就是这道闸。

112 笔、2000 次、seed=42（比特级可复现）：真实 +1.16% vs 随机 +0.39%（p=0.215）；
单笔 Sharpe 0.056 vs 0.032（p=0.430）；胜率 33.9% vs 随机 **45.1%**（p=0.994）。
H₁ 是"真实 ≥ 随机"，所以 p≈1 的含义是真实入场**比随机日子更差**。

读法限制：只随机化入场日得到的标准误来自**股内日间波动**（约 0.6–1.0%），比 DSR/Newey-West/
bootstrap 用的**跨股** σ≈20.9%/笔 窄一个数量级。这里 p 很小只能说明"对这些股票，事件日好过
随便一天"，不能说明信号可泛化；"择时无效"和"绝对边际不过零点"可以同时成立。
不要引用它作为策略有效的证据，也不要说它没实现。

## 保守成交口径

同一条 bar 同时碰到 TP 和 SL 时**按亏损结算**（日内高低点证明不了先后）；跳空穿过触发价时按
**当日开盘价**成交；出场日的净值曲线按成交价结算，这样 `daily` 和 `return_pct` 不会互相矛盾。

同一批 110 笔，乐观口径 +2.34%/笔、利润因子 2.65 → 保守口径 **+0.98%/笔**、利润因子 2.19、
胜率 33.6% [25.5%, 42.7%]（不变）、年化 0.30%、Sharpe 0.08、出场 TP 32 / SL 73 / TIME 5、
平均亏损 −13.19%。保守那一侧才是真实数字，乐观的要标注成旧口径。
这轮对比**没有入库产物**：它是 2026-10-24 口径修正那次手工测的，仓库里搜不到，引用时说清出处
是这个 skill 自己，不要装作能从当前代码复跑出来。

**别把两轮数字串用**：上面 +0.98%/33.6%/Sharpe 0.08 属于 110 笔那一轮。
当前样本是 112 笔，`data/plan_e/plan_e_backtest_v2_latest.md` 的全貌为：净 +1.16%/笔、
胜率 33.9% [25.0%, 42.9%]、年化 0.50%、夏普 0.12、最大回撤 −23.63%、盈亏比 2.21、
出场 TP 33 / SL 74 / 其余 5、平均亏损 −13.15%（比 −10% 止损更深，因为跳空按开盘成交）。
两轮均值差 0.18 个百分点，引用前先确认自己在说哪一轮。入库的记录是 `docs/PLAN_E_LIVE.md`；
`data/` 不入库，克隆下来没有 v2_latest 是正常的。

新回测/模拟脚本必须委托 `tdxfeed/execution/single.py` 的 `settle_single_trade`，不要另写
"先 TP 后 SL"的循环（2026-10-28 收编）。`plan_e_backtest._settle_from_entry` 与
`plan_e_sim_live.simulate_trade` 现均走该内核，差异只在入场时点与 `insufficient`
（前者 `"skip"`、后者 `"last_close"`）；闸门是 `tests/test_plan_e_backtest_exit_fills.py`
与 `tests/test_plan_e_sim_live_exit.py`，钉住三种情形：双触发 ⇒ SL、低开穿 SL ⇒ 开盘、
高开穿 TP ⇒ 开盘。

## 结论是什么

112 笔刷新样本什么都拒不了：DSR p **1.000**，Newey-West 日均值 p **0.748**，
bootstrap 均值对 H₀=0 的 p **0.561**，胜率对盈亏平衡 p=0.296，随机择时 p=0.215/0.994。
均值 +1.16%/笔，95% CI **[−2.6%, +5.1%]**，年化 0.50% 对最大回撤 −23.63%（Calmar 0.02）。

样本量也补不回来：当前 112 笔 μ=+1.16%/笔、σ=20.89%/笔，按 `n=(z·σ/μ)²` 双侧 α=0.05 要 ~1,240 笔、
单侧 α=0.05 且 80% 功效要 ~1,997 笔（两档基准不同，`docs/PLAN_E_LIVE.md` 开头引用的是 1,240 那一档）。
而漏斗一年只出 ~17 笔：112 笔摊在 2020-02-07 → 2026-08-27 共 6.55 年里只有 104 个信号日，
绝大多数交易日的清单是空的 ⇒ 补样本要 70 到 117 年。
跨度和笔数都能重算：逐笔日期在 `data/plan_e/` 的那份 csv 里（不入库），`entry_date` 去重后除以跨度年数。

方案 E 与 daban 都已退出实盘入口，研究产出保留、人工记账保留。
**调度 ≠ 实盘入口**：`plan-e-today.timer` 和 `plan-e-journal.timer` 在 2026-10-24 当晚被重新启用，
恢复的只是盘前清单的**自动生产**，清单本身仍是研究产物（`mode_daily` 不再按它算每只股票的买入量）。
`monitor` / `weekly` / `real-refresh` 保持 disabled。

- 不要为了"修好重新启用的 timer"去翻转 `PLAN_E_PREMARKET_LIST_ACTIVE`。它为 `False` 是有意的，
  只闸门 `plan_e_journal.py` 里的**晚间 CLI 兜底**：18:10 那次读的是当日收盘数据，算出来的
  `entry_date` 是明天，新鲜度守卫本来就会丢弃，白付一次全市场扫描还会覆盖掉今天那份清单。
  清单复用路径根本不看这个常量。
- 不要提议删掉 `--mode buy/sell` 或归档已退役的 plan-e 单元文件：用户明确选了"保持现状：
  只留研究，人工记账也不动"。
- 不要重新清扫 `data/plan_e/` 里 2026-09-27 → 2026-10-12 那一段 v2 报告——已核实它们**根本没有**
  DSR/二项检验章节，带的是陈旧数字而非错误结论。只有 `plan_e_backtest_v2_latest.md` 是当前口径。
  三类缺陷的分册记录写在 `data/plan_e/_pre_fix_20261024/README.md`，那份 README 本身也在
  `data/` 里、不入库；份数会随定时任务变，核对依据是「有没有那一章」而不是数字。
- bootstrap / 置换的种子是固定的：两次运行数字不同说明**数据变了**，不是 RNG 变了。
